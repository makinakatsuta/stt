# サウンドテーブルテニス（STT）

現在のリリース：**v3.31.22**（2026-09-23）

音を聞いてボールの位置を判断し、自分でラケットを左右に動かして返球するブラウザゲームです。音声案内、スクリーンリーダー向けの通知、配色・文字サイズの設定を備えています。ヘッドホンまたはイヤホンでのプレイをおすすめします。

現在遊べるのは **CPU対戦** です。オンライン対戦は一時停止中です。

## すぐに遊ぶ

1. [v3.31.22のリリース](https://github.com/makinakatsuta/stt/releases/tag/v3.31.22)からWindows x64用ZIPをダウンロードして展開します。
2. 展開した `stt.exe` を起動します。`docs` フォルダーはexeと同じ場所に置いてください。
3. ブラウザで `http://localhost:8080` を開きます。8080番ポートが使用中の場合は、起動時に表示されたURLを使います。
4. 「オーディオを有効にして開始する」を押し、「CPU対戦」から難易度を選びます。

## 3つの難易度

| 難易度 | こんな遊び方ができます |
|---|---|
| **簡単（Easy）** | ゆっくりした球と広い返球判定で、気軽に楽しめます。ラリーはサーブを除く双方の返球を合計4回までとし、長引く前にCPUが取り逃します。 |
| **ノーマル（普通／Normal）** | コースを読んで動く試合練習です。CPUは中央・左右・空いている側を狙い、ときどき遅球を返します。相手を大きく左右に動かすと得点しやすくなります。 |
| **ハード（難しい／Hard）** | CPUが速球と遅球をランダムに打ち分けます。CPUの移動も速く、プレイヤーの返球判定はノーマルより厳しめです。 |

**どの難易度も、移動と返球はプレイヤー自身が操作します。** CPUの緩急選択はCPUの打球だけに適用されます。プレイヤーの球速選択や自動追尾はありません。

ノーマルには、実際の返球回数やコースに応じた短い振り返りがあります。難易度選択画面の「普通モード：得点後に短い振り返りを読み上げる」でオン・オフを切り替えられます。設定は同じブラウザに保存します。

ノーマル・ハードには難易度独自のラリー回数上限はありません。後述の促進ルールは別途適用されます。ノーマルの「双方合計6〜10回程度」はバランス調整の目標であり、保証される回数ではありません。

## 基本操作

| 操作 | パソコン | スマートフォン・タブレット |
|---|---|---|
| ラケットを左右に動かす | 左右矢印キー | 対応端末を水平に持ち、体を左右に動かす |
| サーブの準備・返事・サーブ・返球 | Spaceキー | 画面をタップ |
| 試合を中断する | Escapeキー | 中断ボタンをタップ |

球の音が近づいたら、ラケットの横位置を合わせて返球します。スクリーンリーダー使用時は、通常のタップの代わりにダブルタップで操作します。

中断メニューでは再開、操作方法の確認、TOPへの移動ができます。TOPに戻って試合を終了すると、進行状況は失われます。試合終了後や中断画面から難易度を選び直して、新しい試合を始めることもできます。

## 表示・音声・スマートフォンの設定

起動画面で次の設定を変更できます。

- **配色**：標準、黒背景・白文字、白背景・黒文字、黒背景・黄色文字。
- **文字サイズ**：100%、125%、150%、200%。メニュー・得点・案内に適用します。
- **音声の速さ**：0.5〜2.0倍。

スマートフォンから接続する場合は、サーバーを起動したパソコンと同じWi-Fiに接続し、サーバーに表示されたLAN内のURLを開きます。端末の設定で「体を左右に動かしてラケットを操作する」をオンにし、センサーの許可を求められたら許可してください。

センサーの利用可否は端末・ブラウザ・接続方法によって異なります。LAN内のHTTP接続で画面を開けても、センサーが使えない場合があります。その場合はHTTPSでの利用環境を用意するか、外付けキーボードを使ってください。

対象環境はWindows 11のChrome・Edge・Firefox、Androidの対応ブラウザ、iPhone・iPadのSafariなどです。今回の変更について、これらすべての実機検証が完了しているわけではありません。

## 試合のルール

- 1ゲーム11点先取。10対10以降は2点差が必要です。
- 3ゲーム中2ゲームを取るとマッチ勝利です。
- サーブ権は通常2ポイントごと、10対10以降は1ポイントごとに交替します。
- 1ゲームが10分経過すると、9対9、または両者8点以上かつ一方が10点以上の場合を除き、促進ルールを適用します。
- 促進ルール中はレシーバーが7回返球するとレシーバーの得点です。適用後は同じマッチの残りゲームにも引き継ぎます。

STTのルールを参考にしたゲームで、簡単モードのラリー上限やCPUのミス判定など、遊びやすさのための独自調整を含みます。

## 困ったとき

- **音が出ない**：開始ボタンを押したか、端末・ブラウザの音量とイヤホン接続を確認します。必要なら再読み込みして開始し直します。
- **スマートフォンで動かない**：センサー設定・許可・接続方法を確認します。端末を傾けるのではなく、水平に持って体を左右に動かします。
- **ページが開かない**：サーバーが起動しているか、表示されたURLとポート番号が合っているか確認します。
- **更新が反映されない**：exeと同じ版の `docs` を使い、ブラウザを再読み込みします。画面下部の番号と `stt.exe --version` を確認してください。

## 開発・動作確認

GoとNode.jsを使います。プロジェクトのルートでサーバーを起動します。

```powershell
go run main_server.go
```

Go側の物理処理を変更した場合はWebAssemblyを再ビルドします。以下はWindows PowerShell用です。

```powershell
$env:GOOS = 'js'
$env:GOARCH = 'wasm'
go build -o docs/main.wasm main_wasm.go
Remove-Item Env:GOOS, Env:GOARCH
```

難易度のテストを実行します。ノーマルのテストはビルド済みのWASMも読み込むため、Go側を変更した場合は先に再ビルドしてください。

```powershell
node docs/easy-rally.test.cjs
node docs/normal-rally.test.cjs
node docs/hard-rally.test.cjs
node docs/settings-flow.test.cjs
go test ./...
git diff --check
```

Windows x64版をビルドして番号を確認します。

```powershell
$env:GOOS = 'windows'
$env:GOARCH = 'amd64'
go build -trimpath -o stt.exe main_server.go
Remove-Item Env:GOOS, Env:GOARCH
.\stt.exe --version
```

exeはGit管理の対象外です。配布時は同じバージョンの `docs` を同梱します。サーバーの `appVersion`、画面下部、README、読み込みURLのバージョンをそろえ、[リリースノート](release-notes.txt)に変更・検証・未確認事項を記録してください。公開済みのタグや履歴は書き換えません。

自動テストはロジックの確認です。実機での音の聞き取りや遊び心地、未対応項目は [ToDo.md](ToDo.md) で管理します。

保存がブラウザに拒否された場合も設定は現在のセッション内で利用できます。この場合、再読み込み後の保存復元はできません。

ノーマルの自動計測はPowerShellで `$env:STT_BENCHMARK = '1'` を設定してから `node docs/normal-rally.test.cjs` を実行します。2026-09-23の各200ラリーでは平均返球回数がJS版7.03、WASM版6.81でした。これは位置合わせを自動化した仮想プレイヤーの結果で、実プレイヤーの成績ではありません。WASM側の乱数により再実行時の数値は変わります。
