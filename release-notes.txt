バージョン 3.31.42 (2026年10月6日リリース)
-----------------------------------------
【変更内容】
【公開状況】
・ソース版はv3.31.42です。同じコミットをv3.31.42タグで固定し、Windows x64版stt.exeとSHA256SUMS.txtをGitHub Releaseで配布します。実行ファイルはソース管理に含めません。
・配布先：https://github.com/makinakatsuta/stt/releases/tag/v3.31.42

【Hardモードの再調整】
・ラリーができてもCPUが返し続けて得点につながりにくかったバランスを再調整しました。Normalより難しい位置付けを維持しながら、得点と練習による勝利の可能性を持たせています。
・CPUの固定99%返球を廃止。CPUを左右へ動かす返球、速い返球、長いラリーほどCPUがミスしやすくなります。
・Hardのラケット移動速度をNormalと同じ11へ変更し、返球受付を縦95、横の余裕50へ拡大しました。
・CPUサーブのコースはストレート50%、左25%、右25%。速度は遅球15%、通常60%、高速25%で、高速サーブの縦速度を7.5〜8.8へ抑えました。これはCPUサーブの調整で、プレイヤーのサーブとは区別します。
・ラリー加速を1.03、最高球速を14へ調整。双方の返球回数が0のCPUショット計画は予想到達位置から±30以内のストレート寄り、1〜5返球では±90、6返球以降は±150を基本とします。余裕がある後半は30%の確率で空いた側へ130〜160の攻撃を行い、以前の極端なコースを抑えています。
・CPU返球速度は返球回数0の計画で7.5〜8.2、1〜5返球では7.8〜8.8、6返球以降8.2〜9.5です。Normalより速い球と厳しい配球は残しています。
・最終CPU返球率は 0.955 - pressure * 0.025 - min(0.01, max(0, incomingSpeed - 8) * 0.0025)。双方合計6返球以上で0.02、12返球以上でさらに0.025を引き、0.88〜0.955に収めます。

【Normal】
・最終Hard返球率調整では、実ブラウザで良好だった現在のNormalを維持しました。ラケット速度、CPU速度、返球受付、返球率、球速、サーブ、ラリー加速・最高球速を変更して難易度差を作ることはしていません。
・ただしv3.31.41タグとの累積差分には、先行作業で行われたNormalの配球変更が含まれています。中央基準の配球から、CPU側への予想到達位置を基準とする返球回数0の計画±15、1〜5返球では±80、6返球以降±120の配球へ変更されています。「v3.31.41からNormalの全ロジックが不変」という意味ではありません。
・現在のNormal定数・固定seedのショット計画をnormal-balance.jsonで固定し、最終Hard調整および今回の公開準備ではfixtureを変更していません。

【アクセシビリティ表記の整理】
・現在のSTTは、視覚に頼らず主に音を利用してプレイする卓球ゲームです。既存の3Dボール音、実録打球音・サーブ音、スクリーンリーダー通知、キーボード操作を維持しています。
・過去の記録にある難聴者向け対応という表現を、現在の専用方向案内機能が存在するとの説明に使いません。検討・削除された方向補助音や返球補助音は今回の新機能に含めていません。
・navigator.vibrate()が利用可能な端末・ブラウザでは、ラケットの中央位置確認の補助として25msの振動を使う処理を維持しています。難聴・盲難聴・片耳難聴向けの専用方向案内ではなく、左右移動方向や返球タイミングを振動で伝える機能でもありません。
・v3.31.41以前のリリース本文は当時の記録として保持しています。過去の機能説明は現在の実装・対応範囲を保証するものではありません。ToDoとコードコメントにも現在の条件を明記しました。

【JS/WASM・配布手順】
・CPUショット計画はJavaScriptで生成し、JS/WASM両方で共有します。WASM物理にもJS側の乱数源を渡し、固定seedの検証を再現可能にしました。
・AGENTS.mdに、ソース変更後のテスト、必要なWASM再生成、最新ソースを埋め込んだWindows x64版stt.exeの必須再ビルドと--version確認を記録しました。
・最新docs/main.wasmを再生成し、Windows x64版stt.exeを-trimpath付きで再ビルドしました。--versionの出力はSTT v3.31.42。ローカル起動でHTML・JS・WASM・実録音源が作業ツリーの最新ファイルと一致することを確認しました。これはブラウザでの実プレイ確認とは区別します。

【テスト】
・最新WASMを再生成し、node tests/difficulty.test.cjsを省略オプションなしで実行。JS/WASMの両方で200試合ずつ検証しました。
・通常の仮想プレイヤー：JS/WASMともにEasy 200勝/200試合・2200得点、Normal 171勝/200試合・2136得点、Hard 6勝/200試合・958得点。
・熟練Hard仮想プレイヤー：JS/WASMともに94勝/200試合・1799得点。通常Hardより総得点・勝利数が増え、Normalより勝利数は少ない結果でした。
・Hard CPU返球成功（各4000回）：JSはラリー初期3817回、長ラリー3625回。WASMはラリー初期3825回、長ラリー3608回。
・これらは自動テスト内の仮想プレイヤーによる結果であり、実プレイヤーの勝率を示すものではありません。
・Hardの最低600得点・最低3勝、熟練Hardの最低40勝、上達による得点・勝利数の改善、Normalより大きい横移動量・movement effort、Normal固定値・ショット計画、JS/WASM整合性を確認しました。
・difficulty、game-input-accessibility、serve-announcement、speech-system、motion-control、visitor-counterの6つのNodeテストが成功。go test ./...も成功（Goテストファイルはなく、パッケージのビルド確認）。git diff --checkを確認しました。

【実プレイ】
・最終調整前は全盲プレイヤーの実ブラウザ確認でHardのラリーは可能でしたが、ほとんど得点できず楽しさに欠けるとのフィードバックがありました。
・最終調整後のWindows＋NVDAでの実ブラウザプレイは、ユーザーによる検証済みです（2026年10月6日）。使用ブラウザの詳細は未指定です。

バージョン 3.0 (2026年6月13日リリース) - メジャーアップデート
-----------------------------------------
【変更内容】
・CPU戦（Normal/Hard）において2ポイントごとにサーブ権が交代する機能を導入し、プレイヤー側からサーブを打つSTT本来の掛け合いを体験できるようにしました。
・スペースキーまたは画面タップの長押し（最大1.5秒）によりサーブ速度を変化させるチャージサーブ機能を追加し、長押し中にチャージ音が上昇するピッチ合成を再生するようにしました。
・打ち返し判定の判定幅を難易度別に調整（Easy=50px / Normal=30px / Hard=20px）しました。
・得点後の4秒間のインターバル待機中に、スペースキー押下やタップ操作で即座に次のラリーへ移行できるスキップ機能を実装しました。
・試合結果画面において勝者と最終スコアを表示し、「もう一度プレイ」または「メニューに戻る」を選択できるように改善しました（6秒の自動退出は廃止）。
・ボールが通過した横位置（左/中央/右）の方向から失点音が鳴るようにし、ミス方向ガイド音のステレオパンニングに対応しました。
・ボール停止時に、そのX座標に応じたステレオ定位で「コトン」という停止音を再生する処理を追加しました。
・ボール転がり音の音量計算式を Math.log1p に変更し、低速域での音量変化を豊かにすることで、リアルな転がりの減速感を表現しました。
・ウェルカム画面に音声速度スライダー（0.5〜2.0倍）を追加し、設定値を localStorage に保存して永続化する機能を追加しました。
・WebSocket接続を維持したまま、対戦終了後に「もう一度プレイ」ボタンで同期して再戦できるリマッチ機能を実装しました。
・オンライン対戦時の切断後5秒以内に同じルーム・クライアントIDで再接続すれば、試合を継続できる猶予処理を追加しました。
・ルームIDを入力して接続することで、最大5名まで対戦を観戦できる観戦モードを追加しました。
・ゲームの各種設定（難易度、チルトON/OFF、サーバーアドレス、音声速度）を localStorage に保存し、次回起動時も維持されるようにしました。

バージョン 1.1 (2026年6月3日リリース)
-----------------------------------------
【変更内容】
・オンライン対戦におけるWebSocket通信とゲーム同期の不具合（4件）を修正しました。
  1. ping メッセージが対戦相手に誤ってブロードキャストされる問題を修正（サーバー側でインターセプトし pong を返す）。
  2. パドル位置送信の過剰な負荷を抑えるため、30msのスロットル処理をクライアント側に実装。
  3. ネットワーク遅延によるボール位置のズレを防ぐため、Player2は物理計算をスキップし、serve / ball_hit イベント受信時のみ位置を同期するよう修正。
  4. 得点時のバグを防ぐため、Player2はローカルでの得点判定処理を行わず、ホスト(Player1)から送られる point メッセージに従ってスコアを更新するよう修正。
